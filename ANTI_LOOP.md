# Zona Android TV — анти-луп и журнал экспериментов

Последнее обновление: 2026-10-30. Цель — рабочая Zona без видеорекламы, с воспроизведением и возможностью получать **только наши** обновления. Не менять другие репозитории.

## Статус

**НЕТ подтверждённой рабочей NoAds-сборки.** Автоматическая публикация NoVAST заблокирована. Не объявлять очередную сборку рабочей только из-за валидной подписи, ZIP или успешного GitHub Actions. После изменения обязателен тест на ТВ: запуск фильма, реклама в начале и конце, переход через «Пропустить», переход к следующей серии, аккаунт/избранное.

## Что подтверждено инфраструктурой
- Оригинал `zona5.apk`: Zona 3.0.76, package `mobi.zona`; оригинальная подпись зафиксирована.
- Наша сборка подписывается пользовательским сертификатом (SHA-256 `1ae0e98bbf5c2206fa537593f15170d614419be68e7029c70cac7d18754ae8b1`), не выдавать ключ в Git.
- `GitHub Actions` выпускает APK в релиз; установка, отключение рекламы и автообновление из самого приложения — **отдельные проверки**, пока не подтверждены.
- `updates/latest.json` содержит `status: blocked`, без доступного обновления.
- Восстановительная сборка `zona-1076-recovery` возвращает исходный код плеера, но содержит рекламу и ещё не проверена на конкретном ТВ.

## Процесс следующей диагностики (не ходить по кругу)
1. Сравнить **DEX-методы** оригинала и `FreeZona_3.0.76_ultra_aligned.apk`: выявить не только VAST XML, но все реальные изменения рекламных флагов, таймеров, перехода к плееру и обновлений.
2. Отделить рекламное видео от сообщения «установите последнюю Zona»: не считать их одной веткой без доказательств.
3. Составить минимальный diff и контрпроверку веток ошибок до сборки.
4. Не публиковать как стабильную и не направлять в автообновления без подтверждения пользователем полного просмотра на ТВ.
5. После каждой новой неудачи дописать сюда: файл, метод, гипотеза, наблюдение и причина; откат к последнему работающему видео.
