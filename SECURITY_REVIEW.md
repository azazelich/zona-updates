# Zona 3.0.76 — сравнительный аудит перед собственной сборкой

**Проверено 31.10.2026.** Цель: создать собственный APK на базе официальной Zona с точечными самостоятельно проверенными изменениями, используя FreeZona только как функциональный контрольный образец. **Собственной подтверждённой рабочей NoAds-сборки пока нет.**

## Исходные образы и воспроизводимость

- Официальный APK `zona5.apk`: SHA-256 `bd6b8eb66a9f2c45e6b95a372f1b7c0891bba898eb0ca7cb33c5102690561b8c`, package `mobi.zona`, version `3.0.76`.
- FreeZona `FreeZona_3.0.76_ultra_aligned.apk`: SHA-256 `aa3c36ab5faa1770104b1f3347d52ad72270ec377b5f7684acc2323df70ba021`, package `free.zona`, version `3.0.76`. Получен из релиза `julay123/mobi.zona`.
- Проверочный код: [`tools/audit_apks.py`](tools/audit_apks.py), выполняет read-only анализ APK, проверяет указанные SHA-256, перечень разрешений и нативных библиотек, контрольные байты заданных DEX-методов.
- Независимый запуск GitHub Actions [`Audit original Zona against FreeZona`](https://github.com/azazelich/zona-updates/actions/runs/41183854939) **успешен**. Никакие приватные signing secrets не используются; APK не публикуются. Подтверждены результаты ниже.

## Положительные результаты и реальная зона риска

| Контроль | Официальная Zona | FreeZona | Что это значит |
|---|---:|---:|---|
| Различающихся разрешений | 20 | 17 | FreeZona **не добавляет новых** разрешений Android. Отсутствуют три рекламных разрешения |
| Нативные библиотеки `.so` | 40 | 20 | FreeZona удаляет для всех 4 ABI библиотеки `libzona.so` и четыре библиотеки AppMetrica |
| Перенаправление `Cookie` видеозапроса | `Lid/a.a(...)` | `zona.Cookie(...)` | Разная реализация, важная для получения потока; **почему** она работает, ещё не доказано |
| Нативные проверки времени/подписей | Оригинальные `CppUtil` вызовы | `zona.checkTimeNative123` и изменённые вызовы | Существенное вмешательство, которое нельзя переносить вслепую |
| Логика оплаты (`LPh/d`) | Проверка `isPaid`, дат, `Order.id` | Изменённые условия | Исключить из переноса |
| Реальный просмотр на тестовом Android TV | Оригинальная Zona работала, но с рекламой | **Успех: поток, фильм, звук, рекламы нет** | Есть рабочий контрольный образец на том же устройстве; не доказывает безопасность его кода |
| Собственная Recovery (наш сертификат) | Не применимо | **Неудача:** реклама есть, но поток заменяется QR-заставкой | Просто переподписать оригинал недостаточно |

Три разрешения, отсутствующие в FreeZona:
- `android.permission.ACCESS_ADSERVICES_AD_ID`
- `android.permission.ACCESS_ADSERVICES_ATTRIBUTION`
- `android.permission.AD_SERVICES_CONFIG`

**Критическая оговорка:** разрешения — лишь один слой безопасности. Отсутствие новых разрешений **не доказывает**, что неизвестный код не передаёт конфиденциальные данные по уже разрешённому `INTERNET` или не вмешивается в аккаунт. Работающий на ТВ фильм также ничего не говорит о доверии к автору модификации.

## Принцип создания собственной версии

1. **Основой остаётся только официальная Zona 3.0.76**, проверенная по оригинальному сертификату. Мы не берём FreeZona целиком, не переименовываем её и не выдаём переподписание за аудит.
2. **Маршрут потока:** адресно исследуем `Lvd/d.b` → оригинальный `Lid/a.a` и эталонный `zona.Cookie`; сравниваем назначение параметров, формирование cookie и ответ сервера. Не копируем токены и реальные значения cookie в публичный GitHub.
3. **Проверки среды:** изучаем `CppUtil.checkTimeNative[2]` и вызовы, но не переносим обфусцированную замену до понимания её зависимостей и поведения.
4. **Рекламный этап:** только после запуска фильма; старые подмены пустого VAST и no-media VAST уже провалили тесты.
5. **Ограничения:** сохранение регистрации/избранного, текущего пакета `mobi.zona`, собственного сертификата пользователя (fingerprint `1ae0e98bbf5c2206fa537593f15170d614419be68e7029c70cac7d18754ae8b1`), безопасных механизмов обновления и однозначного rollback. **Не изменять `Order.isPaid`, подписки или платёжную модель.**
6. **Gate выпуска:** никакого объявления рабочим APK лишь по подписи/zipalign. Для следующего кандидатного APK нужно показать точный минимальный diff и пройти реальные проверки запуска двух фильмов, отсутствия рекламы/QR, следующей серии и повторного открытия; до этого `updates/latest.json` заблокирован.

## Что ещё не установлено

- Точные входные данные и семантика `zona.Cookie` (функция содержит обфусцированные таблицы и операции, а не просто переадресацию URL).
- Возвращается ли QR-заставка из-за различия cookie, собственной подписи, нативной проверки либо сочетания факторов. **Пока нет причинного доказательства.**
- Безопасность полного FreeZona APK, механизма авторизации и самообновления не подтверждена аудитом.
- Полностью независимый, проверенный эквивалент затронутых функций пока не создан. **Не выпускать фиктивный «безопасный» собственный APK на базе непроверенного кода.**

Данный отчёт фиксирует **завершённый сравнительный этап**, а не сертификат безопасности приложения.
