# Сравнение APK Zona 3.0.76 и FreeZona 3.0.76 (статический анализ)

Дата: 2026-10-30. Только локальный анализ двух APK, без запуска и передачи закрытых ключей.

Контрольные SHA-256:
- Оригинал `zona5.apk`: `bd6b8eb66a9f2c45e6b95a372f1b7c0891bba898eb0ca7cb33c5102690561b8c`.
- Образец `FreeZona_3.0.76_ultra_aligned.apk`: `aa3c36ab5faa1770104b1f3347d52ad72270ec377b5f7684acc2323df70ba021`.

## Что реально различается в DEX

| Файл DEX | Совпадающих имён методов | Методов с изменённым байткодом | Методов с изменившимся размером |
| --- | ---: | ---: | ---: |
| classes.dex | 57 518 | 9 | 0 |
| classes2.dex | 4 758 | 1 | 0 |
| classes3.dex | 60 785 | 6 | 0 |
| classes4.dex | 51 185 | 28 928 | 9 |

**Не считать все 28 928 изменений самостоятельными патчами:** большинство содержит сдвинутые индексы строк, полей и методов из-за перепаковки DEX. Укорочено фактически 9 методов. Весь порядок/набор классов тоже отличается.

### Обнаруженные смысловые изменения (оригинал → FreeZona)

- `LPh/d;.a(LPh/c;J)Z`: проверяет в `LPh/c` поля `isPaid`, `startDate`, `endDate` (длительность/дату заказа); во FreeZona **всегда возвращает true**. Это затрагивает логику заказа, а не просто видеорекламу.
- `LPh/d;.b(LPh/c;)Z`: проверяет `Order.id == -1`; во FreeZona **всегда возвращает false**. Класс `LPh/c` имеет `toString` с идентификатором `Order(id=..., isPaid=...)`.
- `Lod/e;.invoke()`: вызов `CppUtil.Companion.eso()` заменён на `null`.
- Два корутинных маршрута `App$e.a` и `Cd/e$c.a` больше не вызывают прежние `CppUtil.Companion.checkTimeNative[2]` в прежнем виде; рядом присутствует замена `mobi/zona/utils/CppUtil` на `mobi/zona/utils/zona` с новым нативным методом `checkTimeNative123`.
- Также изменены `Lvd/r;.invokeSuspend`, `Ltd/h;.<init>`, `Lkd/g;.a`, `Lru/zona/app/android/App;.onCreate`. **Назначение и безвредность этих изменений ещё не установлены**.

### Конфигурация FreeZona
В новом литерале FreeZona есть список `api` (серверы Zona), `update` и `vast` (GitHub raw другого автора), `stream`, `image`. Заявленные в её README действия: реклама отключена; пакет переименован; ориентация изменена; собственное обновление.

## Вывод для нашей сборки

1. **Не переносить патчи FreeZona целиком:** среди них есть вмешательство в модель `Order` и вызовы `CppUtil`, не только отключение VAST. Это нарушает принцип точечных изменений и усложняет проверку безопасности.
2. **Не повторять** пустой VAST или один VAST без `MediaFile`: они уже дали зависание рекламы и QR-заставку на ТВ-боксе.
3. Требуется установить *где именно* начинается и завершается реклама, как формируется следующий вызов `startPlayback` и кто возвращает `NO_ADS_VAST_RESPONSE`. Пока эти связи не проверены, новая «идеальная версия» **не готова**.
4. Отключение рекламы и собственное автообновление — разные задачи. Сначала корректное воспроизведение без рекламы, потом доставка новых APK.
5. Никогда не объявлять APK рабочим по одному успешному `apksigner`/`zipalign`.

Источник: локальный статический анализ двух предоставленных APK и `julay123/mobi.zona` README; это не динамическое подтверждение отсутствия рекламы/угроз.


## Углублённая проверка по двум APK — 31.10.2026

Сравнение выполнялось по приложенным `zona5.apk` (официальная Zona 3.0.76) и `FreeZona_3.0.76_ultra_aligned.apk`: построены индексы методов DEX, сопоставлены ссылки на вызываемые функции в указанных ниже методах. Это статическая проверка, а не подтверждение работы на ТВ.

### 1. Главное отличие в запросе видеопотока — HTTP Cookie

Метод **`Lvd/d;->b(LI9/f;Lkotlin/coroutines/Continuation;)Ljava/lang/Object;`** имеет по 202 DEX code units в обеих версиях. Он добавляет заголовок с именем **`Cookie`** в запрос. Критическое отличие в инструкции, формирующей значение:

| Original Zona | FreeZona |
|---|---|
| `invoke-static Lid/a;->a(JLjava/lang/Object;)Ljava/lang/String;` (code-unit offset 158) | `invoke-static Lmobi/zona/utils/zona;->Cookie(JLandroid/content/Context;)Ljava/lang/String;` (offset 158) |

Оригинальный `Lid/a.a` — ~1927 code units, с большим количеством рефлексии и обфусцированных строк. В FreeZona новая `zona.Cookie` — 557 code units. **Здесь реально подменён алгоритм создания cookie, а не косметика рекламы.** Невалидные/отличающиеся cookie потенциально могут объяснять серверную заглушку «скачайте Zona» вместо потока, но результат сервера пока не наблюдался непосредственно.

### 2. Внутренние проверки

- В `Lru/zona/app/android/App$e;->a(...)` оригинальные вызовы `CppUtil$Companion.checkTimeNative` и `checkTimeNative2` (и условный выбор между ними) FreeZona заменяет вызовом собственного `zona.checkTimeNative123`.
- В `LCd/e$c;->a(...)` аналогично заменён вызов `checkTimeNative` на `zona.checkTimeNative123`.
- `App.onCreate()` больше не вызывает `java.lang.System.loadLibrary`; четыре исходные `libzona.so` действительно отсутствуют в моде. `Lvd/r.invokeSuspend` перестаёт вызывать `CppUtil$Companion.d()`; `Lod/e.invoke` перестаёт вызывать `eso()`.
- Это подтверждает модификацию нативной/контрольной подсистемы, **но не доказывает, какая именно проверка вызывает QR**.

### 3. Конфигурация серверов — оговорка по реальному исполнению

FreeZona добавляет в DEX шестнадцатеричную строку, которая декодируется в JSON с ключами `api`, `update`, `vast`, `stream`, `image`; там есть адреса `apiwn1.mzona.net`, `apirn1.mzona.net`, `vsw01.zonasearch.com`, `vsr01.zonasearch.com` и собственный GitHub для обновлений/VAST.

**Важно:** текст JSON введён инструкцией `const-string v23` в `Lkd/g.a(String)` непосредственно перед `return-object v0`. В этом месте регистр `v23` перед возвратом не используется. Следовательно, наличие JSON в DEX **само по себе не доказывает**, что именно эти адреса реально выбираются при воспроизведении. Нужно проследить потребителя строк/контекст конфигурации. Существование отдельных `getUpdate` конфигураций FreeZona на GitHub установлено независимо.

### 4. Что переносить нельзя

FreeZona дополнительно меняет `Order.isPaid`/срок оплаты в `LPh/d`. Эти изменения **не относятся к установлению работоспособности видеопотока**, их нельзя переносить в наш проект без отдельного обоснования. Нельзя копировать весь `classes4.dex`, поскольку это внесёт изменения оплаты и недоверенный обфусцированный код.

### 5. Проверяемая следующая гипотеза

Проверить **маршрут формирования/приёма cookie видеопотока** (`Lvd/d.b`, `Lid/a.a`, `zona.Cookie`) прежде, чем снова менять рекламу/VAST. Учитывать связанный `checkTimeNative`, но не объявлять его виновником заранее. В идеале сравнить на одном устройстве и сети HTTP-статусы/коды ошибок без сохранения токенов/cookie или проверить оригинал на проблемном устройстве с предупреждением о смене подписи и потере данных.

**Статус:** рабочего NoAds APK с воспроизведением пока нет. Выпуск/автообновление остаются заблокированы.
