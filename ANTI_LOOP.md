# Zona Android TV — анти-луп и журнал экспериментов

Последнее обновление: 2026-10-31. Цель — рабочая Zona без видеорекламы, с воспроизведением и возможностью получать **только наши** обновления. Не менять другие репозитории.

## Статус

**НЕТ подтверждённой рабочей NoAds-сборки.** Автоматическая публикация NoVAST заблокирована. Не объявлять очередную сборку рабочей только из-за валидной подписи, ZIP или успешного GitHub Actions. После изменения обязателен тест на ТВ: запуск фильма, реклама в начале и конце, переход через «Пропустить», переход к следующей серии, аккаунт/избранное.

## Правила инженерной проверки и журнал результатов — 31.10.2026

**Требование владельца:** записывать в этот документ **успехи, неудачи, частичные результаты и неподтверждённые проверки**. Приоритет — глубокий разбор причин и доказательства, а не генерация новых гипотез или APK наугад.

### Для каждой работы фиксировать
1. **Объект:** дата, исходный APK и его SHA-256, версия/versionCode, точный изменённый DEX-метод или конфигурация, commit, GitHub Actions run и ссылка на release — там, где применимо.
2. **Наблюдение:** что произошло на реальном ТВ, модель бокса и сеть (если известны), тот же фильм/источник для сравнения; разделять сообщения пользователя, результаты статической проверки, журналы установки и сетевые ответы.
3. **Проверка по этапам:** сборка, подпись/zipalign, установка, запуск приложения, наличие рекламы, пропуск рекламы, **старт реального фильма**, наличие QR-заставки, избранное/аккаунт, обновление установленной версии. Для каждого: **УСПЕХ / НЕУДАЧА / ЧАСТИЧНО / НЕ ПРОВЕРЕНО**. Успешный workflow НЕ означает работающий плеер.
4. **Причинная связь:** конкретные подтверждённые факты → одна проверяемая причина → что могло бы её опровергнуть. Не выдавать корреляцию за причинность и не смешивать сравнение двух боксов с сравнением двух подписей.
5. **Риск и возврат:** способ отката с пометкой возможной потери данных, сохранение сертификата/пакета/versionCode и блокировка публикации неиспытанного APK.
6. **Решение:** почему изменение принято, отклонено либо отложено; какой конкретный вывод даёт даже отрицательный тест.

### Запрет на угадывание
- До нового патча **проследить цепочку** от клика «Воспроизвести» до запроса потока и ответа плеера, используя статические вызовы и (при доступности) диагностические логи/HTTP-статусы **без раскрытия cookies/токенов**.
- Для модификаций FreeZona проводить **семантический** diff вызовов/ветвей, а не переносить целиком DEX, нативные библиотеки или изменения оплаты/подписки; сторонняя обфусцированная реализация не является проверенным эталоном безопасности.
- Сводить варианты к **одной обоснованной контрольной проверке** на одном устройстве и одном фильме. Не выпускать серию пробных APK, различающихся только догадками о VAST, версии или URL.
- Если доказательства недостаточны, явно записать «причина не установлена» и **не публиковать** новое приложение. Статическая целостность — лишь необходимое, но не достаточное условие.
- Не включать `updates/latest.json` и автоматическую публикацию NoAds до подтверждения на ТВ: минимум два разных фильма без рекламы и QR, повторный запуск, переход между сериями и проверка сохранности данных.

## Дополнительная проверка DEX 30.10.2026
- Подтверждено **по декомпилированным строкам и полям**: `LPh/c` — модель `Order(id, partnerId, userId, startDate, endDate, isPaid, priceId, paymentMethodId, ...)`.
- FreeZona меняет проверку `LPh/d.a(Order, time)` с условий `isPaid` + дат на константу **true**, а `LPh/d.b(Order)` с проверки `Order.id == -1` на константу **false**. Значит, эти изменения затрагивают **логику платежей / подписок**, а не просто VAST. **Не переносить их без обоснования и не заявлять, будто все изменения FreeZona относятся только к рекламе.**
- `Lod/e.invoke()` вместо вызова `CppUtil.eso()` возвращает `null`; также изменены нативные проверки `checkTimeNative`, `App.onCreate` и иные маршруты. Их безопасность и отношение к плееру не подтверждены.
- В оригинале найдено отдельное исключение `VAST response is empty`; это подтверждает, что предыдущая подмена VAST на пустую строку была принципиально неверным вариантом.
- Два APK содержат сотни тысяч методов; в `classes4.dex` **28 928 отличий байт-кода при совпадающих именах** в основном объясняются переиндексацией DEX, поэтому нельзя переносить «всё отличающееся» без семантического сравнения.

## Эксперимент № 3 — 2026-10-30: InstreamEmptyList (не проверен на ТВ)

- **Гипотеза:** корутинный метод `IPlayerInstreamAdServiceKt.adsBeforePlayback` (`classes4.dex`, `Ldg/i;.a(Ldg/f;Lzg/k;ContinuationImpl;)Object`) сам возвращает `List` после подготовки видеорекламы. Его штатная ветка обработки таймаута уже использует `CollectionsKt.emptyList()`. Если сразу вернуть тот же пустой список, рекламная вставка может быть пропущена **до** входа в рекламный плеер.
- **Изменение:** замена первых пяти DEX code units на вызов существующего `CollectionsKt.emptyList()`, `move-result-object`, `return-object`; размер DEX и 143+ оставшихся code units не меняются. Ни `VastResponse.getVast()`, ни модель `Order`, ни медиа-плеер, ни пароль/подпись не меняются.
- **Статические проверки:** версия исходника `3.0.76`, `versionCode=1076`, исходный сертификат и исходные байты метода жёстко сверяются. ZIP alignment, APK v1/v2 signatures, diff единственного DEX подтверждены GitHub Actions.
- **Сборка:** [Zona 3.0.76 InstreamEmptyList TEST](https://github.com/azazelich/zona-updates/releases/tag/zona-1076-instream-bypass-experiment), SHA-256 `3ddc48e38b39cb3a1b7de09dfa8134627f9bf67dedc78238096cc410d7ff785a`.
- **Результат на Android TV:** **ещё неизвестен**. Требуется проверить: исчезла ли реклама, начинается ли фильм, работает ли «Пропустить» если появляется, не возникает ли QR-заставка «установите последнюю Zona», играет ли следующее видео.
- **Запрет:** не считать успех GitHub Actions подтверждением работоспособности. Не обновлять `updates/latest.json` и не включать автоматическую публикацию до фактического теста.

## Дополнительная диагностика QR-заставки — 2026-10-30

**Уточнение пользователя:** экран «Для просмотра видео скачайте и установите последнюю версию Zona» появляется **именно при попытке запустить фильм**, а не при открытии приложения. В тесте `InstreamEmptyList` обычная реклама исчезла, но фильм не воспроизводится.

**Проверка независимых сообщений:** точно такая формулировка встречается не только в модификациях. На 4PDA описан случай с **официальной актуальной** Zona, где загрузка фильма возвращала ту же заставку, например декабрь 2023: https://4pda.to/forum/index.php?showtopic=377461&st=5340 ; при другом случае автор сообщил, что с **модификацией без рекламы** получал такую заставку, а штатная Zona показывала рекламу, февраль 2026: https://4pda.to/forum/index.php?showtopic=377461&st=13160 . Это делает гипотезу «экран однозначно является антимодификационной защитой» **недоказанной**. Возможны недействительная ссылка на видео/поток, несовпадение серверного API/заголовков клиента, география/сеть и отказ проверки приложения.

**Новая находка при сравнении оригинала с FreeZona:** модифицированная FreeZona удаляет `libzona.so` (для arm64-v8a, armeabi-v7a, x86, x86_64), а также нативную `CppUtil` и добавляет сильно обфусцированный программный заменитель `mobi.zona.utils.zona`. Значит, её исправление сетевого запроса/аутентификации **не сводится к** VAST XML или `adsBeforePlayback`. Перенос такой обфусцированной замены из неизвестной сборки без анализа несёт отдельный риск.

**Следующий контроль:** сравнить просмотр **того же фильма и источника** в оригинальной Zona 3.0.76 и в нашей сборке на **том же ТВ-боксе и сети**. Если QR появляется даже в оригинале, исправление рекламного DEX не решит серверную/сетевую ошибку. Если только в модификации, исследовать формирование сетевого запроса к потоку и нативный `CppUtil`, не трогая модель оплаты `Order`.

**Не выпускать** новый тестовый APK по очередной случайной подмене VAST. Нужны причинная связь и контроль воспроизведения.

## Дополнение 30.10.2026 — проверка по оригинальному и FreeZona DEX и внешним случаям QR

- Проверка 76 инструкций метода `Ldg/i;.a(Ldg/f;Lzg/k;ContinuationImpl;)Object` (**adsBeforePlayback**) показала: после нормализации ссылок на классы, методы, поля и строки **все 76 инструкций семантически совпадают** между `zona5.apk` и `FreeZona_3.0.76_ultra_aligned.apk`. Хэши сырых байтов различаются только из-за переиндексации DEX; **у FreeZona нет нашего патча мгновенного `emptyList()`**.
- FreeZona добавляет отдельную строку — шестнадцатеричное представление JSON с ключами `api`, `update`, `vast`, `stream`, `image`; среди хостов — `apiwn1.mzona.net`, `apirn1.mzona.net`, `vsw01.zonasearch.com`, `vsr01.zonasearch.com`. Также удалены нативные `libzona.so` по четырём ABI и заменены вызовы `CppUtil`. Нельзя считать это проверенным и безопасным переносимым патчем.
- **Независимые внешние отчёты, январь 2026:** в теме Zona на 4PDA несколько модификаций без рекламы также отдавали QR при просмотре; у некоторых пользователей работа зависела от VPN/региона или прекращалась спустя время. Источник: https://4pda.to/forum/index.php?showtopic=377461&st=11900 . Другой отчёт про мод без рекламы и исправление другого автора: https://4pda.to/forum/index.php?showtopic=377461&st=13160 . Это поддерживает гипотезу серверного ответа/политики для видеозапросов, но **не доказывает её**.
- **Критический следующий контроль:** на том же боксе открыть **тот же фильм** из `zona-1076-recovery` (оригинальная логика видео, но **наша подпись**) и сравнить с `zona-1076-instream-bypass-experiment`. Оба APK подписаны одним ключом. Если recovery с рекламой воспроизводит фильм, проблема в изменении рекламного этапа; если recovery также показывает QR, нужно исследовать серверные требования к подписи/запросу/сети. Этот тест устраняет главный конфаундер — разные сертификаты.
- **Нет доказательств**, что подмена версии `9.9.99` или простая смена VAST решит серверную QR-заставку. Повторять бессмысленно.
- Новый стабильный APK запрещён до воспроизведения как минимум двух разных фильмов без рекламы и без QR, включая повторный запуск после закрытия приложения.
